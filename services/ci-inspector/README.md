# OMG CI inspector

As of 2026-10-20, the owner has deployed all three OMG Workers. Full hosted repair-to-PR acceptance remains pending. See [adaptation research](../../docs/operations/cloudflare-ci-adaptation-research.md) and [activation questions](../../docs/operations/cloudflare-ci-research-open-questions.md) for the handoff basis and remaining gates.

Owner-only, stateless inspection of caller-supplied CI evidence for `omg-cli/omg`. The Worker does not fetch GitHub, execute builds, rerun jobs, change source or store snapshots. The caller collects actual GitHub evidence and chooses what to send to Workers AI. Repository and commit fields describe that submitted evidence and do not independently attest its origin or freshness.

`POST /inspect` requires `Authorization: Bearer <CI_INSPECTOR_TOKEN>` and `Content-Type: application/json`. Configure the bearer token as a Worker secret. No GitHub credential belongs on the Worker.

The body contains `repository`, `runId`, `branch`, `sha`, `prompt` and `jobs`. Each job contains `id`, `name`, `status`, nullable `conclusion` and `failedSteps`. Each failed step contains `name` and `log`. See `src/snapshot.ts` for the exact schema. Additional fields and duplicate job IDs are rejected. Uploads are limited to 128 KiB, 20 jobs, six failed steps per job, 12,000 characters per log and 2,000 characters per prompt. The CLI must disclose any truncation when it collects evidence.

Code Mode exposes only `listJobs` and `readFailedStep`. Tool arguments are parsed again at execution, with a shared 12-call budget. The sandbox has no environment bindings or outbound network access. The executor timeout is 10 seconds. The model loop allows four steps, 800 output tokens per step and no automatic model retries. A 30-second abort signal is supplied to the model SDK. Provider-side cancellation and synchronous sandbox CPU termination need real platform acceptance. The Worker CPU setting is 1,000 ms.

The model is `@cf/deepseek-ai/deepseek-v4.1-flash-1017`, with explicit `reasoning_effort: none` through per-call Workers AI provider options. This uses the direct AI binding. No AI Gateway is configured. Inference and Dynamic Worker usage incur their published platform charges. Grant eligibility and invoice deductions require separate confirmation.

Responses contain the supplied identity plus `summary`, `model`, `usage`, `codeExecutions` and `snapshotToolCalls`. A summary requires at least one completed Code Mode call and one successful snapshot tool call. Summaries are capped at 16,000 characters. The service has no payload logging or enabled Worker observability. Responses use `Cache-Control: no-store`. This is an advisory explanation. Its output is not a required CI check or proof that a test passed.

From this directory, use Bun 1.4.4 and run `bun install --frozen-lockfile`, `bun test`, `bun run check` and `bun run build`. Build performs a Wrangler dry run. There is deliberately no deploy script. Unit fixtures verify request admission and tool behavior. A deployed acceptance must separately establish the exact model call, actual sandbox tool composition, blocked egress and runtime limits using an isolated snapshot.

The source type check imports Cloudflare's official exported runtime types and uses `runtime.d.ts` to connect dependency ambient names to those exact declarations, avoiding conflicting Worker, Node and browser global declarations. Source and Bun tests have separate TypeScript contexts, with full dependency declaration checking and no `skipLibCheck` or diagnostic suppressions.

## Source and PR review

`POST /review` uses the same owner authorization. Its strict request contains `repository`, exact lowercase 40-character `sha`, `branch`, `changedPaths`, `diff`, `sourceFiles` and optional `ciFailures`. Each source file contains `path`, `blobSha` and exact UTF-8 `content`. Each CI failure contains `job`, `step` and `log`. Requests admit at most 512 KiB, 30 changed paths, 64,000 diff characters, 12 source files of 24,000 characters each, and six CI logs of 8,000 characters each. Paths reject traversal and duplicate entries. Every supplied file's Git blob SHA-1 is recomputed before inference. This verifies the submitted bytes against the submitted blob identity. The external verifier must still establish that GitHub associates that blob with the supplied path and commit.

The four read-only Code Mode tools list supplied file metadata, read bounded source line ranges, read diff chunks and read optional CI failure records. They receive no GitHub credentials or command execution capability. Source reads admit at most 80 lines and 12,000 characters, diff reads at most 12,000 characters, and a shared budget admits 18 tool attempts. At least one successful source read and completed Code Mode call are required.

The selected provider currently omits tool definitions when JSON-schema output is enabled. Review therefore uses at most three tool-enabled model steps followed by one tool-free structured-output call over the actual tool response messages. The same DeepSeek model and explicit `reasoning_effort: none` apply to both phases. Tool steps allow 2,000 output tokens each; the structured phase allows 6,000. There are no automatic model retries. Both phases share a 60-second abort signal, subject to the provider cancellation limitation above. Sandbox execution retains its 10-second timeout and blocked egress.

The response is discriminated by `kind`. `no-findings` has a summary. `candidates` has a summary and at most three candidates. Each candidate has `title`, `impact`, exact source `evidence`, nullable `proposedFix` and service-owned `verification: uncorroborated`. Evidence includes `path`, `blobSha`, `lineStart`, `lineEnd` and a verbatim `quote`. Invalid quotes, ranges or identities reject the response. All successful responses include identity, actual model usage for each phase, `codeExecutions`, `sourceToolCalls` and `publication: requires-verifier`. The source and response contracts are exported by `src/review-contract.ts` and `src/review-http.ts`.

Responses also include `suppliedPaths`, `readPaths` and `readDiff`. A path enters `readPaths` only after a successful source read; a nonempty successful diff read sets `readDiff`. Candidate evidence must reference a path actually read. These receipts attest source excerpts and touched diff chunks, not complete file or diff coverage. The trusted collector reports supplied but unread files explicitly and does not claim model review during `--snapshot-only` collection.

A proposed fix contains at most three exact, unique `oldText`/`newText` source replacements and one new regression test. Existing tests and configuration files are not admitted source edit targets. For OMG Rust proposals, the designated test path for candidate N is `tests/ci-review-<first12CommitSha>-N.rs`. The inspector retains the original JavaScript path policy additively, but the OMG coder, verifier and publisher admit the Rust production-source and designated Rust regression policy; inspector schema acceptance alone does not authorize publication. Its record includes `content` and `expectedTestName`. The service can check only the submitted path set; the external verifier must reject a designated path that already exists elsewhere in the complete Git tree. It must also execute the named meaningful assertion against the intact base and patched source, distinguish product failures from setup failures, run affected portable checks, and establish patch/commit identity before any verified regular fix PR publication for human review. A model proposal and matching source quote alone do not establish a bug or passing fix. The service has no publication tools.
