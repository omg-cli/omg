# Worker type boundaries

These patches correct Worker type boundaries and preserve reviewed runtime behavior. The Sandbox patch awaits RPC disconnects, retains the stopped client identity and checks execution fences. The Containers patch checks the lifecycle hook before starting a replacement. The CI patch validates acknowledged process completion and retains immutable raw logs.

- `@cloudflare/containers@0.3.7` uses the official Worker Request and Response types at its container boundary.
- `@cloudflare/sandbox@0.12.14` uses the same Worker Request, Response and ReadableStream types at its public container boundary.
- `@cloudflare/ci@0.2.0` carries Worker streams from Sandbox through runner logs into Workflow steps. Its local constructor declaration describes the actual Worker global and emits no JavaScript.
- `capnweb@0.8.0` maps tuple elements without spreading a union containing promises. Optional positions, readonly tuples, variadic tails and promise values retain their types.

Run `bun run check` to compile source, Bun tests and public API type fixtures separately. `type-tests/capnweb-tuples.ts` checks valid and invalid RPC argument shapes without diagnostic suppressions. `type-tests/worker-boundaries.ts` checks actual Worker requests, responses and persisted log streams.

The [official Worker typing guide](https://developers.cloudflare.com/workers/languages/typescript/#generate-types) recommends generated types for applications and workers-types for shared libraries. The [reported Node/Worker stream conflict](https://github.com/cloudflare/workers-sdk/issues/6211) explains why mixing ambient type families changes API assignability. The installed [Containers source](https://github.com/cloudflare/containers) and [native CI source](https://github.com/cloudflare/ci) target Workers. Sandbox 1.x changes the runtime API and is not a drop-in typing correction for this pinned 0.x pipeline.

The recovery design adapts CodeLoud commit `9552eb2d12155a4c9b00029a0fb651b082cee310` to OMG's pinned Sandbox 0.12.14. Before launch, the CI SDK records execution ownership in private R2. After `startProcess()` acknowledges launch, it reads canonical server metadata through `getProcess()` and records the exact process ID, command hash, actor and original deadline. Client and server start timestamps must not be compared as if they were identical.

An admitted Workflow interruption can recover a completed receipt or resume observation of that exact acknowledged process. A conditional R2 write claims the existing single runtime recovery allowance. Missing, changed, expired or previously claimed ownership fails closed. Command launch and checkout are never repeated after acknowledgement. The Workflow stores primitive JSON checkpoints and verifies retained log and snapshot integrity before admitting recovered completion. See [Workflow replay rules](https://developers.cloudflare.com/workflows/build/rules-of-workflows/), the [Sandbox 0.x command API](https://developers.cloudflare.com/sandbox/sdk/api/commands/) and [RPC resource ownership](https://developers.cloudflare.com/workers/runtime-apis/rpc/lifecycle/).

OMG's redacted caller-error capture, lifecycle fences and terminal-state consistency checks remain in place. Both directions of disagreement between terminal state and exit code are refused. `sdk-workflow-logs.test.mjs` retains the original failure matrix against the new process boundary. `sdk-durable-recovery.test.mjs` additionally exercises canonical metadata, single-claim recovery, wrong actors, changed deadlines, capability disposal, cancellation acknowledgement and corrupted evidence through the actual SDK and Workerd/R2. The deadline fixtures incorporate the observation-clock correction from CodeLoud PR 257 at `61a11254568c0bef596853b4cb4d9eb16e146aa4`; that unmerged test correction requires OMG's own executed verification.
