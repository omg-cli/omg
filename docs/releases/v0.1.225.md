# v0.1.225 beta release

This release brings the accumulated package, runtime, daemon and verification changes since v0.1.224 into one published version. The [complete comparison](https://github.com/omg-cli/omg/compare/v0.1.224...v0.1.225) includes the individual fixes and verification records.

## Security changes

- Native Arch/AUR admission displays disclosed affected-version and watch-list findings with advisory links. Installing them requires a foreground terminal's exact `accept <review-id>` answer. Generic `--yes`, blank input, EOF, signals and unattended execution cannot accept that risk. Approval binds the prepared transaction, principal, policy and artifact bytes; it does not override source, license, signature or archive requirements.
- Managed npm tools resolve an exact, bounded dependency lock before materializing packages or running lifecycle scripts. OMG checks every distinct direct/transitive registry version through OSV, requires separate consent for findings, rechecks accepted evidence and rejects changed lockfiles or runtime binaries. Frozen installation retains signature verification and separately scoped script permission. Failures preserve an existing working tool.
- Node downloads authenticate the signed checksum manifest against pinned active Node releaser certificates before selecting the archive digest. Unknown, expired, revoked and invalid signers are refused. There is no unsigned fallback or personal keyring mutation. Builds without PGP support refuse new Node downloads.
- Arch/AUR transaction, private staging/build, elevation, provenance, cancellation and Omarchy migration boundaries receive the accumulated hardening in this release. The ALPM dependency family is pinned to an immutable upstream commit.

## Advisory service

The deployed Cloudflare service provides an indexed rolling 30-day view of stored CVE revisions, retained older records, Arch advisories and CISA KEV annotations. Public responses use bounded caching and ETags. FIRST EPSS enrichment supplies dated probability/percentile values and up to 30 days of available history for imported CVEs. Genuine zero, missing scores, stale scores and provider failures remain distinct; failed refreshes retain previous history without asserting a current score.

The CVE baseline remains incomplete. Missing records and unsupported package mappings remain Unknown. EPSS is prioritization context, not proof of safety or current exploitation. Zero Wire content is not redistributed without verified permission. Public feeds cannot establish the absence of undisclosed zero-days.

## Native packages, runtimes and daemon

This release includes the intervening Arch, Debian/Ubuntu and Fedora package/daemon fixes, runtime and environment ownership/restore fixes, bounded process lifecycle work, and stricter real QEMU acceptance. Linux archives distinguish Debian Bookworm's APT 6 ABI from Debian Trixie's APT 7 ABI. OMG and omgd remain a matched release pair; restart an already running daemon after updating.

## Upgrade notes and coverage limits

- Managed npm tools now require an active OMG-managed Node with bundled npm >=11.15.0. Use a current supported Node release. Ambient npm, private registries, registry aliases and non-registry resolver sources are not accepted by this gate. Existing Windows NVM/Node/npm installations are not migrated.
- npm lifecycle scripts remain disabled unless separately allowed for that exact package. CVE acceptance does not grant script or unverified-signature permission.
- The attended npm risk prompt currently requires Linux terminal ownership checks; macOS does not yet have equivalent consent support. Known findings are refused there.
- The new attended native consent applies to Arch/AUR. Other native backends do not yet have equivalent consent. Runtime publisher authentication and EOL reporting do not establish runtime-vendor CVE coverage; vendor-specific runtime advisory admission remains unfinished.
- Older Node releases signed only by excluded historical authorities may be refused. Selecting an existing installation does not reverify its download provenance.
- Windows testing uses WSL and the Linux build. This release does not introduce a native Windows package backend.

## Release provenance and project maintenance

The release pipeline requires exact-commit CI, security, coverage, benchmark and native acceptance before publication. It collects six platform archives with checksums, includes a locked CycloneDX SBOM, generates GitHub/Sigstore build provenance and attaches `omg-release.sigstore.json`. Verify downloads against the source tag and release workflow, as described in the generated release instructions. R2 publishes the latest-version marker only after archive/checksum round-trip verification.

GitHub Sponsors links the maintainer's existing public profile. The repository now includes Contributor Covenant 2.0, maintainer-led governance and OpenSSF Scorecard publication alongside the existing security reporting policy. Grant or fiscal-host acceptance is not implied by these files.
