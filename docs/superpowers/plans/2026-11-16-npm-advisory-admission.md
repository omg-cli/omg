# npm advisory admission

The user delegated the implementation choice and requires attended, scoped acceptance of disclosed package risk before installation. Use npm's own lock-only resolver followed by a frozen `npm ci`, the existing bounded OSV client and advisory-review model. This plan implements that requirement; it does not change source or signature policy.

## Research and caller inventory

`src/cli/tool.rs` owns managed installation, update, staging, signature verification, optional script rebuild and final publication. A blocking worker owns the complete transaction even after async caller cancellation. Its two cancellation tests and fake npm fixtures must follow the extra resolution phase without weakening their ownership assertions. Registry fallback currently rejects version selectors, preventing the requested exact-vulnerable-version test. `PiManager` also shells out to ambient npm and has separate install/use callers. `NodeManager` manages authenticated release archives and exact installed versions. No existing managed npm resolver was found; do not treat Pi's ambient executable as one.

`VulnerabilityScanner` bounds response bytes, findings, pagination and concurrency, but its ordinary assessment accepts distribution origins and parses distro versions. npm coordinates must use their own explicit origin and exact version strings. Never forge `DistributionPackage` or query Node core as the npm `node` package. `AdvisoryRiskReview` already binds findings, provenance, inventory and caller transaction context and validates the exact `accept <digest>` answer. Native Arch's prompt is privileged and Linux specific; reuse its cancellation and foreground-terminal requirements without giving registry installs root authority.

Official references, checked 2026-11-16:

- https://docs.npmjs.com/cli/v11/commands/npm-install/ documents `--package-lock-only` resolution.
- https://docs.npmjs.com/cli/v11/commands/npm-ci/ documents frozen complete-project installation and `--ignore-scripts`.
- https://google.github.io/osv.dev/post-v1-query/ requires exact ecosystem/name/version and continuation tokens; a partial page sequence is not complete coverage.
- https://docs.npmjs.com/cli/v11/using-npm/changelog/ records all four `allow-git`, `allow-file`, `allow-directory` and `allow-remote` controls by npm 11.15.0. Require that minimum from the bundled npm metadata and explicitly disable those non-registry sources before lock resolution. Rejecting a Git/URL lock only afterward is too late to constrain resolver fetches. Do not assume an older npm enforces unknown flags.

## Complete transaction

1. Validate registry package spec, allowing a bare or scoped registry name with an optional exact semantic version. Keep the user-facing installation name separate from its version selector. Reject URLs, aliases, local paths, Git, range selectors and malformed package names before mutation.
2. Resolve an installed, contained OMG-managed Node release and its bundled npm CLI. Execute that npm with the absolute managed Node path under the existing restricted manager environment, closed child stdin and no new privileges. Preserve Windows Node/npm. Missing managed Node gives an actionable setup error, never a fallback to ambient npm.
3. In the existing private staging transaction, resolve `package-lock.json` with scripts disabled, no audit side effects, explicit registry and no package materialization. Bound and validate the v3 lock: root identity plus all direct/transitive nodes, actual npm names including scoped/nested packages, exact versions, HTTPS registry tarballs and integrity fields. Reject links, aliases, Git, uncontained paths, malformed or incomplete inventories. Retain all platform/optional entries conservatively.
4. Assess each distinct exact npm coordinate with the existing bounded OSV transport. Show unavailable/partial coverage truthfully; never cache a failed/partial response as clean. Produce findings with exact package attribution and safe advisory URLs. Include the complete lock digest, requested package, manager, install destination, current effective source/signature/script options, principal and managed runtime identity in the review binding.
5. On findings, display the review and require an attended foreground terminal's exact transaction-bound answer. Decline, blank, generic yes, EOF, absent terminal, timeout and cancellation stop before `npm ci`, lifecycle scripts or activation. Revalidate lock bytes and runtime/policy identity before materialization and publication; changed evidence invalidates consent. Preserve old working installations on any error.
6. Run frozen `npm ci --ignore-scripts`, retain existing mandatory signature/provenance checks, then the separately scoped script permission if present. Verify the installed inventory matches the reviewed lock; do not silently re-resolve. Publish through the current rollback-safe path and write the exact review/evidence identity to the security receipt.
7. Route install/update and Pi's npm dependency installation through the shared owner. Activation/restoration must not bypass runtime advisory admission. Extend supported runtime vendor matching separately; missing mappings remain Unknown.
